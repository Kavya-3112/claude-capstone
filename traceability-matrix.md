# Requirement-to-Test Traceability Matrix

**Produced for Stage 5 task T-25** ("consolidate E2E and unit tests so each FR/NFR has at least one test; record a requirement-to-test matrix"), 2026-10-23.

**Method:** every FR-01..FR-57 and NFR-01..NFR-11 in `requirements.md` was checked against the test files under `tests/unit/` and `tests/e2e/`. Test names below are the Vitest `describe > it` title or the Playwright `test.describe > test` title, taken from the actual file read, not from stale comments. Where a comment in a test cited an FR/T-xx id, the assertion body was read to confirm the mapping actually tests that behaviour before it was relied on here; a few comment-only references that did not hold up are noted inline.

**Scope note:** this pass maps requirements to existing tests and records gaps. It does **not** deduplicate or consolidate the suites (no tests were merged, renamed, or removed), and it does **not** add any new tests to close the gaps found — both are out of scope for this task per the Orchestrator's delegation.

**Caveat on approval chain:** `impl-plan.md`'s own banner states the plan "rests on unverified approvals" and was written under a user-gate override; `requirements.md` records Q-08 and Q-15 as still open. This matrix takes the already-IMPLEMENTED Stage 5 tasks (T-00..T-21, T-24 partial) and their existing tests as given, per the Orchestrator's delegation of T-25 specifically; it does not itself verify or re-open those approvals.

Legend: **Test** = at least one test exercises the requirement (unit and/or e2e, file + test name given). **Gap** = no test exists; a named reason is given, honestly distinguishing a deferred/out-of-scope item from a real gap.
